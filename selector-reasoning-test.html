Selector Reasoning Test

Three sections that require AI to reason about element type, position, and DOM depth — not just text or class names.

Section 1 — Same Text, Same Class, Different Element Types

innerText: "Test"  ·  class: "test-item"  ·  no IDs

Five elements — <div>, <a>, <input>, <button>, <select> — all share the same class and visible text. The element tag name is the only discriminator.

Section 2 — Repeated Identical Elements

10 × <button class="repeat-item">Test</button>  ·  no IDs  ·  no distinguishing attributes

All ten buttons are completely identical in markup. A positional selector is required: :nth-child(n), :nth-of-type(n), or index-based equivalents. Position numbers shown are for visual reference only — they are not part of the element.

Section 3 — Deeply Nested Structure

10 levels of <div class="nest-item">  ·  labels: <span class="nest-label">  ·  no IDs

Each level of nesting contains a span.nest-label. The only way to target a specific label is by counting ancestor .nest-item divs — e.g. .nest-item .nest-item .nest-item > .nest-label selects "Test 3".

Section 4 — ARIA & Semantic Attribute Deception

class: "aria-item"  ·  text: "Submit"  ·  same across all 6 elements

Three <div>s and three <button>s — all with the same class and text. Each carries a different semantic hook: role="button", aria-label, or id. Tag-type selectors alone can’t distinguish the three divs from each other, nor the three buttons from each other.

Section 5 — Table Navigation

5 × 5 data grid  ·  class: "cell-item"  ·  text: "Cell"  ·  no IDs

All 25 data cells are identical: same class, same text, no IDs. Selecting a specific cell requires a positional approach such as tbody tr:nth-child(3) td:nth-of-type(3) for Row 3, Col C.
